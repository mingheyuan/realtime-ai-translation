# 客观指标基线

## 固定测试协议

- 日期：2026-08-28
- 输入：macOS 系统音频
- ASR：Sherpa-ONNX，`zh-CN`
- 翻译方向：`zh-CN → en-US`
- 快速翻译：MarianMT
- 终稿：项目本机配置的 DeepSeek 快速非思考模型
- 语音文本：[`source-zh-en.txt`](source-zh-en.txt)
- LLM 合成背景：[`context-zh-en.txt`](context-zh-en.txt)，623 个字符
- TTS：`say -v Tingting -r 210`，生成音频约 22.019 秒
- 样本：重启服务后的 1 次冷启动试验，以及 3 次配置一致的预热试验
- 正式基线：3 次预热试验逐项取中位数，并由 `/api/metrics/baseline` 持久化

复测时先生成完全相同的音频：

```bash
say -v Tingting -r 210 \
  -f benchmarks/source-zh-en.txt \
  -o /private/tmp/realtime-translation-benchmark.aiff
```

## 质量观察

- 数字 `2026`、否定、问题/要求语气在三个热运行的可见终稿中均得到保留。
- `Realtime Translation` 在可见终稿中保持为英文实体。
- `DeepSeek` 实体纠正只有 1/3 次成功；另外两次分别保留为 `DEEP C` 和 `DEPTH`。这说明“背景中存在正确实体”还不能保证模型稳定纠正 ASR，同一测试的实体命中率基线为 33.3%。
- ASR 前缀回改率 0% 只表示 Sherpa partial 很少修改已经显示的前缀，不代表 ASR 内容完全正确。实体命中率和后续用户纠正率仍是必要护栏。

## 阶段 2 验收线

阶段 2 的背景检索与缓存只有同时满足以下条件才算完成：

- 主指标：每段发送的参考背景中位数从 623 字符至少下降 50%，即不高于 311 字符。
- 主指标：LLM 总输入 P50 至少下降 5%，即不高于 5363 字符。
- 质量指标：`DeepSeek` 实体命中从 1/3 提高到至少 2/3，目标为 3/3。
- 延迟护栏：LLM P95 不高于 1142 ms，终稿 P95 不高于 1736 ms（均为基线 +10%）。
- 稳定性护栏：短碎片率保持 0%，MarianMT 和 LLM 请求失败保持 0。
- 使用本文件相同协议重新执行 1 次冷启动和 3 次热运行，提交前后结果；未达到以上门槛时阶段 2 保持未完成。
